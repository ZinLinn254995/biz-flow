# P3.1 — State and Handoff Consistency Validator

## Task ID
P3.1

## Objective
Strengthen the existing `verify:ai` mechanism so canonical project-state documents cannot silently disagree about current milestone, last completed task, or authorized next work.

## What changed
- Added `scripts/ai-state-validation.mjs` as a small, exported continuity-validation module used by the existing `scripts/verify-ai-state.mjs` entry point.
- Added explicit development-status vocabulary validation for `ACTIVE`, `PAUSED_AWAITING_INSTRUCTIONS`, and `BLOCKED_ON_HUMAN_DECISION`.
- Added milestone, last-completed-task, and paused/authorized-next-task consistency checks for `AI_HANDOFF.md` and `CURRENT_STATE.md`.
- Added focused tests covering valid state, historical references, status values, milestone drift, task drift, invalid status, paused active tasks, and stale onboarding state.
- Corrected the genuinely current P2P18 text in `AGENTS.md` to P2P28; historical P2P18 references elsewhere remain valid history.
- Updated canonical handoff state to identify P3.1 as complete while preserving P2P1–P2P28 product progress at 100%.

## Important decisions
- Kept `verify-ai-state.mjs` as the verification entry point; the new module only isolates pure parsing and validation for focused tests.
- Validation checks identity-bearing task IDs in current-state sections rather than matching prose or historical mentions.
- A paused project must have no machine-authorized `nextTask` and no canonical document may present an executable next task. Descriptive roadmap history is not treated as authorization.
